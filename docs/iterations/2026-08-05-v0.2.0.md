# CodeAtlas v0.2.0 迭代记录

- 开始日期：2026-08-05
- 分支：`codex/v0.2-multi-project`
- 状态：开发完成，PR #1 等待审查与合并
- Pull Request：https://github.com/hanfeng529264/codeatlas/pull/1
- 目标：一个工作空间聚合多个独立项目，并在一个 Web 应用中查看全部、单项目和跨项目依赖。

## 验收标准

- [x] `codeatlas init --empty` 创建空的聚合工作空间。
- [x] `codeatlas project add/list/remove` 管理工作空间项目。
- [x] `codeatlas project scan` 一条命令发现并注册多个项目。
- [x] `codeatlas open .` 自动初始化、发现、索引并打开单项目或多项目空间。
- [x] 至少两个独立 CodeGraph 数据库可以同时加载，原始重复 ID 不冲突。
- [x] 完整空间图显示所有项目和统一总量。
- [x] 用户可以筛选单个项目并随时返回全部项目。
- [x] 搜索遵循当前项目范围。
- [x] 匹配的工作空间包依赖显示为跨项目 `DEPENDS_ON` 关系。
- [x] 一个项目索引异常时有明确状态，不伪装成完整结果。
- [x] 单项目 Schema 1 工作空间无需重新初始化即可继续使用。

## 架构决定

- 使用每项目独立 CodeGraph 索引，CodeAtlas 读取时聚合，见 ADR-0006。
- 工作空间配置升级为 Schema 2，持久化路径保持相对工作空间。
- v0.2 的跨项目证据来自包清单；不推断方法级跨项目调用。
- `main` 保持保护状态，所有开发在功能分支完成后通过 PR 合并。

## 已知限制

- v0.2 只从 JavaScript/TypeScript `package.json` 生成明确的跨项目依赖。
- 项目必须位于工作空间根目录内部。
- 不在本阶段实现方法级跨项目调用解析、MCP 或知识持久化。
- 超大空间默认显示代表性总览；用户仍可显式渲染完整图，但浏览器性能取决于机器配置和图谱规模。
