# ADR-0004：MVP 使用 SQLite 而非独立图数据库

## Status

Accepted

## Context

CodeAtlas 需要保存人工知识、视角、数据源状态和实体绑定，并执行局部邻域、路径和影响分析。图数据库天然支持遍历，但引入 Neo4j 等服务会增加安装、资源占用、迁移和跨平台运维成本。第一版是本地单用户产品。

## Decision

MVP 使用 SQLite 保存 CodeAtlas 自有数据，查询层为热点图构建内存邻接索引，并对所有遍历设置深度和结果预算。CodeGraph 事实仍由其自身数据库管理。只有真实基准证明单机 SQLite/内存方案无法满足规模目标时，才重新评估嵌入式或独立图数据库。

## Consequences

### Positive

- 零服务依赖，安装、备份和恢复简单。
- 事务和 Schema 迁移成熟。
- 与本地优先、单空间场景匹配。
- 人工知识可以作为单文件备份。

### Negative

- 复杂多跳查询需要应用层算法和索引。
- 超大图的内存邻接表需要分块和预算控制。
- 不适合多用户并发写入。

### Neutral

- 投影缓存可删除重建，不属于事实存储。

## Alternatives Considered

- Neo4j：查询能力强，但部署和资源成本不符合 MVP。
- PostgreSQL：适合未来服务化，但本地安装负担较大。
- 纯内存图：速度快，但人工知识和视角缺少可靠持久化。
