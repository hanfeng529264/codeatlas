# ADR-0006：聚合每个项目的独立 CodeGraph 索引

## Status

Accepted

## Context

CodeAtlas 需要在一个工作空间中展示多个真实项目。让 CodeGraph 直接扫描工作空间根目录看似简单，但嵌套 Git 仓库、根目录 `.gitignore`、不同语言工具链和项目独立生命周期会导致文件被忽略、索引失败或同步边界不清晰。将多个项目复制到统一目录或合并数据库也会破坏项目原有结构。

## Decision

每个项目继续在自身根目录维护独立的 `.codegraph/codegraph.db`。CodeAtlas 的工作空间配置保存项目 ID、名称和相对路径；读取时为项目、目录、文件、符号和关系增加项目命名空间，再聚合为一份只读的统一快照。

项目之间的明确依赖由 CodeAtlas 的补充适配器生成。v0.2 首先读取 JavaScript/TypeScript 项目的 `package.json`，当一个工作空间项目依赖另一个项目的包名时，生成项目级 `DEPENDS_ON` 关系，并标记来源和证据类型。后续 HTTP、RPC、事件和其他构建清单使用相同扩展点接入。

## Consequences

### Positive

- 不改变各项目现有 Git、构建和 CodeGraph 工作流。
- 单个项目失败时可以明确报告，不阻塞其他健康项目。
- 节点 ID 在聚合后不会因不同数据库使用相同原始 ID 而冲突。
- 可以独立同步、移除和重新索引项目。

### Negative

- 需要在读取阶段合并多个数据库，并统一处理总量预算。
- CodeGraph 原生关系不会自动跨越两个独立数据库。
- 跨项目关系需要额外适配器，且必须明确证据等级。

### Neutral

- 工作空间仍只启动一个本地 Web 服务，对用户隐藏数据库数量。

## Alternatives Considered

- 在工作空间根目录建立一个 CodeGraph 索引：实现最少，但已被嵌套仓库和忽略规则证明不可靠。
- 将多个 SQLite 数据库复制或合并成新数据库：查询直接，但增加同步、迁移和损坏风险。
- 为每个项目启动独立 CodeAtlas：兼容现状，但无法满足统一全景和跨项目探索。
