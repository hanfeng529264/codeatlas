# ADR-0008：以契约证据连接跨项目调用

- 状态：Accepted
- 日期：2026-08-05
- 决策者：CodeAtlas 项目

## 背景

CodeAtlas 聚合每个项目独立生成的 CodeGraph 索引。项目内调用可以直接复用 CodeGraph，但消费方依赖的 Java contract 通常只存在于二进制依赖中，消费方索引无法解析到提供方源码节点。真实工作空间因此出现 API Route 已连接到本地 Service、core Service 已连接到数据库表，却缺少两者之间的一条跨项目调用边。

仅按方法名连接会在中大型工作空间产生大量误报；把所有源码复制到一个合并索引又会破坏独立项目边界，并重新引入嵌套仓库、构建目录和索引生命周期问题。

## 决策

CodeAtlas 在聚合阶段增加可扩展的“跨项目契约桥接”层。Java/Maven 首个实现只有在以下静态证据同时成立时才生成 `REMOTE_CALLS`：

1. 消费项目的 Maven 依赖坐标指向工作空间内某个提供项目的 artifact；
2. 调用接收者的声明类型能够通过 Java import 还原为完整限定接口名；
3. 提供项目存在该完整限定接口，且方法名与参数个数得到唯一匹配；
4. 调用点能够唯一归属到消费项目的一个 CodeGraph 方法节点。

边保留消费/提供项目、Maven 坐标、接口、方法、参数个数、调用文件和行号等证据。框架特有信息（例如 SCF `ProxyFactory` 与 contract URL）可以由后续 Provider 增强置信度，但不写入通用匹配前提。

候选缺失或不唯一时不猜测、不生成边；可诊断但不会使其他项目不可用。

## 备选方案

### 仅按同名方法连接

拒绝。覆盖率高但误报不可控，无法满足“能验证”的产品目标。

### 合并所有项目后重新运行 CodeGraph

拒绝。会打破 ADR-0006 的独立索引边界，增加扫描范围、嵌套仓库和失败隔离成本。

### 仅实现 SCF 专用解析

拒绝作为核心方案。SCF 证据很强，但会把跨项目模型绑定到单一内部框架；保留为可选增强 Provider 更合适。

## 影响

- 数据链路可以跨越独立项目索引，并保持调用方向清晰。
- `REMOTE_CALLS` 与进程内 `CALLS` 分离，UI 和 API 能表达远程边界。
- 首个实现覆盖 Maven + Java；Gradle、TypeScript workspace、Feign、Dubbo 等可通过相同桥接契约扩展。
- 基于轻量静态解析，复杂表达式、反射、动态代理别名和无法确定类型的调用将保持缺失，而不是被推测补齐。

## 非功能约束

- 构建过程只读源码与 manifest，不连接网络、不执行项目构建。
- 使用坐标、接口和方法索引，复杂度接近 O(节点 + 文件 + manifest)，禁止项目间笛卡尔积匹配。
- 边 ID 和选择顺序必须确定性，重复加载不得产生重复关系。
- 单个 manifest 或源码文件解析失败只产生诊断，不阻断健康项目。
